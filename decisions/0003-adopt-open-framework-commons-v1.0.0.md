# 0003: Adopt Open Framework Commons v1.0.0

- **Status:** Accepted
- **Date:** 2026-08-03
- **Decision owner:** Brad Groux

## Context

Open Framework Commons provides a small shared foundation for independent
ecosystem products. Influence needs a durable public record of whether it has
adopted a Commons revision without letting shared documentation become a parent
framework or silently alter local business guidance.

The reviewed Commons release is annotated tag
[`v1.0.0`](https://github.com/BradGroux/open-framework-commons/releases/tag/v1.0.0),
release commit
[`a0f0d384e9010a65d1a21a324b4c912433d5e031`](https://github.com/BradGroux/open-framework-commons/commit/a0f0d384e9010a65d1a21a324b4c912433d5e031).
Its shared principles align with Influence's existing people-first,
contribution-before-growth, tool-independent, openly governed, and
evidence-bounded practice. Its product-independence boundary leaves Influence's
more specific responsibilities intact.

Commons v1.0.0 previously resolved to
`27870fb1d57d951b9ef5a3a86f33ef068ee557da` and now resolves to
`a0f0d384e9010a65d1a21a324b4c912433d5e031` after coordinated republication.
Refreshing the exact pin changes no Influence method or authority.

## Options

1. **Do not adopt Commons.** This preserves independence but leaves readers
   without an explicit ecosystem relationship.
2. **Reference Commons without a disposition.** This improves discovery but
   leaves authority, deferrals, and possible deviations ambiguous.
3. **Adopt the exact release with an explicit independence boundary.** This
   records shared alignment while keeping every Influence-specific choice
   under local governance.

## Decision

Adopt Open Framework Commons v1.0.0 through option 3.

- Adopt all nine shared principles and the shared boundaries. They reinforce
  existing Influence commitments; they do not replace the charter or canonical
  framework.
- Keep Influence's concerns, method, terminology, examples, research,
  governance, roadmap, implementation choices, and releases product-local.
- Defer Mission Control, community-extension topics, and guidance owned by
  other ecosystem products unless they are separately proposed and accepted
  through Influence governance.
- Record no deviation from Commons v1.0.0. Influence's stronger requirements
  for human judgment, consent, communication boundaries, and external action
  are compatible local guidance.
- Keep Commons outside the Influence authority chain. If an apparent conflict
  arises, surface it and resolve it through the applicable Influence change
  path rather than silently choosing either document.

## Consequences

- `README.md` identifies the exact Commons repository, tag, and release commit
  where readers discover Influence.
- `GOVERNANCE.md` records the adoption and makes local authority explicit.
- Later Commons revisions do not apply automatically. Each requires a separate
  adoption, deferral, or deviation decision.
- This decision changes repository and governance documentation, not canonical
  framework meaning. Because there is no documented use of the initial release,
  the owner directed v1.0.0 to be republished with this adoption. The original
  tag target `7d4727a8cf889d621e45854c874a5e0a15a94a56`, the first
  Commons-adoption target `f91851a1b42b28b01928e5db7aaac4c20b946417`,
  and the immediately prior product target
  `cbe41ccd84f2027f58ae7938df09131b5fbde3ca` remain recorded in release
  evidence.
- After this pin refresh is reviewed and merged, Influence v1.0.0 will be
  republished through the repository's existing release process.
- No software, technical conformance layer, relationship lifecycle, outreach
  system, or guidance owned by another product enters Influence through this
  adoption.
