# Implementation guide

Start small enough to govern well. A useful first implementation can be one profile, one ecosystem question, a handful of fictional or authorized records, one contribution, and one reflection.

## 1. Establish authority

Adopt or adapt the charter. Name the accountable practitioner or group. Record local laws, policies, community norms, accessibility commitments, professional boundaries, and who may approve external engagement.

## 2. Create a profile

Use the profile template to declare mission, goals, non-goals, strengths, capacity, ecosystems, channels, privacy boundary, prohibited actions, and review cadence. Avoid turning goals into activity quotas.

See the [profile-to-framework visual](../visuals/exports/svg/profile-to-framework.svg) and [description](../visuals/descriptions/profile-to-framework.md).

## 3. Choose a bounded question

Select one ecosystem, event, contribution, or learning question. Define why it matters, what evidence is sufficient, how much time and data are proportionate, and what stops the work.

## 4. Build evidence before records

Use the [research method](16-research-methodology.md). Label fact, inference, and hypothesis. Keep public examples fictional. In real private use, collect only necessary authorized data and implement the [private overlay contract](12-ethics-privacy-and-safety.md#private-overlay-contract).

## 5. Map and decide

Create linked records using templates or compatible tools. Prioritize contributions and learning, not people. Make no action, wait, and do not contact available at every decision point.

## 6. Contribute and engage carefully

Plan a concrete contribution with consent and maintenance. Use human-reviewed outreach only when a truthful contextual reason remains. Never give an agent or background job sending authority.

## 7. Reflect and improve

Record expected versus actual outcomes, including rejection and failure. Keep profile-specific lessons local until broader evidence supports a canonical proposal.

## 8. Validate and review

Validate schemas, links, privacy, agent boundaries, diagrams, and indexes. Review the result with affected communities or domain experts when consequences justify it. Report skipped and deferred checks.

## Tool adaptation

Markdown and JSON are the public reference implementation, not a required storage product. A spreadsheet, knowledge graph, database, note system, or workflow tool may implement the same meaning if it preserves stable identity, provenance, authority, privacy, human decisions, corrections, retention, exports, and validation.

## Migration

Record schema and framework version on every portable record. Before a breaking change, publish field mapping, defaults, validation behavior, privacy impact, rollback, and deprecation period. Never migrate a missing or uncertain claim into a fabricated value.
