# Tickets: Influence Operating Framework initial build

These tracer-bullet tickets build the approved [initial specification](../specifications/initial-build.md). Work the **frontier**: any ticket whose blockers are complete.

The owner requested completion of the full build prompt and explicitly authorized conservative resolution of non-blocking gaps. This ticket route is therefore approved by that instruction; architecture, ethics, data-model, or external-action changes still require owner input.

## Establish the governed repository and acceptance seam

**What to build:** A new adopter can open the repository, understand its authority and ethical boundary, run one validation command, and receive a truthful initial result while the remaining slices are incomplete.

**Blocked by:** None — can start immediately.

- [x] Repository authority, governance, contribution, conduct, security, license, changelog, and operator entry points exist.
- [x] The grill review, glossary, specification, decisions, assumptions, deferrals, and implementation status are navigable.
- [x] The top-level validator reports named gates and never converts failures or deferrals into success.

## Demonstrate evidence-backed ecosystem and relationship records

**What to build:** A practitioner can represent a fictional ecosystem as linked people, organizations, events, relationships, interactions, and evidence, then validate the records and their references end to end.

**Blocked by:** Establish the governed repository and acceptance seam.

- [x] Canonical docs define ecosystem mapping, relationship continuity, event intelligence, and research methodology.
- [x] Portable schemas and fictional records cover the corresponding concepts and resolve linked IDs.
- [x] Templates let a human create equivalent records without a specific software platform.

## Demonstrate contribution-first opportunity practice

**What to build:** A practitioner can evaluate a fictional opportunity with explainable, multi-dimensional judgment and choose a concrete contribution before any ask.

**Blocked by:** Demonstrate evidence-backed ecosystem and relationship records.

- [x] Canonical docs define contribution strategy, influence channels, and opportunity evaluation.
- [x] Opportunity and contribution schemas require narrative, evidence, uncertainty, and human judgment.
- [x] A fictional example proves that commercial value is optional and downstream.

## Enforce human-reviewed outreach and reflection

**What to build:** A practitioner can move an evidence-backed draft through approve, revise, wait, or do not contact, without any sending path, and can turn the outcome into a reflection.

**Blocked by:** Demonstrate contribution-first opportunity practice.

- [x] Canonical docs and workflows define the human disposition state machine and external-system boundary.
- [x] Outreach and reflection records validate all required safety and learning fields.
- [x] Tests reject missing dispositions, sending capability, invented familiarity, and attempts to override do not contact automatically.

**What to build:** Brad can use an owner-supplied profile and a fictional noncommercial practitioner can use the same framework, templates, monthly review, and annual plan.

**Blocked by:** Enforce human-reviewed outreach and reflection.

- [x] Brad's profile contains only supplied context and clearly marks its provenance and review limits.
- [x] A second fictional profile demonstrates a community or nonprofit mission without commercial assumptions.

## Specify bounded agents and complete workflows

**What to build:** An implementer can build tool-specific agents from complete, testable contracts while every external action remains human-governed.

**Blocked by:** Enforce human-reviewed outreach and reflection; Apply the framework through reusable profiles and reviews.

- [x] Each required agent contract defines purpose, inputs, evidence, outputs, confidence, prohibited actions, approvals, failures, logging, idempotency, privacy, and tests.
- [x] Each required workflow identifies triggers, decisions, stops, recovery, evidence, and reflection.
- [x] No agent or workflow contains credentials, a sender, or an autonomous external action.

**Blocked by:** Demonstrate evidence-backed ecosystem and relationship records; Demonstrate contribution-first opportunity practice; Enforce human-reviewed outreach and reflection; Apply the framework through reusable profiles and reviews; Specify bounded agents and complete workflows.

- [x] The twelve named concepts have Mermaid sources, deterministic SVG and PNG exports, metadata, and accessible descriptions.
- [x] The visual grammar is documented and source/export hashes are validated.
- [x] Representative renders are visually inspected for readability.
