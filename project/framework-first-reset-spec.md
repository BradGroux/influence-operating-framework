# Framework-first reset specification

- **Status:** Accepted for implementation
- **Owner:** Brad Groux
- **Date:** 2026-08-01
- **Fixed point:** `main` at `b7bcd4d`

## Objective

Rebuild the repository surface as a concise, human-first business operating
framework comparable in boundary and structure to the AI-Native Operating
Framework. Preserve the strong influence concepts while removing the technical
implementation architecture that had become the center of release work.

## Preserve

- Mission and twelve principles.
- Contribution before ask.
- Relationships over transactions.
- Evidence before confidence.
- Human judgment and ethical boundaries.
- A practical, non-funnel operating method.
- Reflection, learning, and multidimensional outcomes.
- Open governance, fictional examples, and an MIT license.

## Remove from the v1 framework

- JSON Schemas, portable record formats, and migrations.
- Automation-agent contracts and sending-system specifications.
- JSON graph fixtures and personal profile machinery.
- Operational template and workflow packs.
- Generated SVG and PNG exports, metadata, manifests, and rendering
  dependencies.
- Technical conformance and release-assurance suites tied to those artifacts.
- Graph architecture as a defining framework layer.

## Target structure

- A canonical `framework/` directory containing a charter, operating framework,
  practice method, responsible-practice standard, measurement and learning
  guidance, and glossary.
- A small set of fictional Markdown examples.
- A decision record fixing the business-framework boundary.
- Inline Mermaid diagrams only where they materially improve understanding.
- Lightweight, dependency-free document validation.
- Project reviews kept separate from canonical content.

## Acceptance criteria

- The repository clearly defines a business operating framework rather than a
  software or data specification.
- A practitioner can understand what to consider, how to apply the method, when
  to stop, and how to learn without adopting a tool or record format.
- People are never treated as leads, scores, targets, or conversions.
- Waiting, declining, no action, and do not contact remain valid outcomes.
- Accountable human judgment governs external engagement.
- Technical implementation choices are explicitly outside framework authority.
- Examples illustrate application without adding requirements.
- Repository links, anchors, structure, version, and Mermaid fences validate.
- All committed Mermaid diagrams render successfully during release review
  using a pinned ephemeral renderer with no checked-in generated exports.
- Two independent reviewers evaluate the exact candidate before final v1.0.0.
