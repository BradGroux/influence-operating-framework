# v1.0.0 release criteria

**Status:** Accepted by [ADR-001](../../decisions/ADR-001-v1-release-assurance-gates.md)
**Owner:** Brad Groux
**Effective date:** 2026-08-01

## Purpose

Version 1.0.0 is a maturity claim, not a version-string change. The release may be committed and tagged only when the exact candidate tree satisfies every required repository, independent-review, reporting, and owner-approval gate below. A technical PASS does not convert an open external gate into release readiness.

## Repository gates

- Canonical documents, schemas, templates, examples, workflows, agents, and visuals agree on human authority, evidence, uncertainty, privacy, contribution-first practice, wait, no action, and do-not-contact.
- Portable records preserve the canonically required accountability and learning meaning, structured unknowns, evidence conditions, temporal invariants, passive extensions, and approval scope.
- Decision histories validate internally and are compared with the last authoritative snapshot before migration or release.
- `python3 scripts/validate.py` passes from a clean checkout with declared dependencies.
- Validation report and visual manifest are byte-stable across unchanged repeated runs.
- All twelve visuals are manually inspected and their accessible descriptions preserve the same material meaning.
- Schema-breaking changes include an explicit migration guide, rollback boundary, and validation differences.
- Version, changelog, status, governance, report, package metadata, release notes, commit, and annotated tag identify the same release tree.

## Independent review gates

- Two fresh-context AI agents independently review the same exact clean candidate SHA: one application/adopter review and one adversarial release-assurance review.
- Both post-fix reports contain zero unresolved Blocker or Material findings.
- The accountable disposition records every finding as fixed, accepted risk, deferred release blocker, or rejected with evidence.
- Qualified human ethics, privacy, accessibility, and relevant domain reviewers complete and disposition their reviews. AI review does not substitute for those accountable judgments.

## Operational gates

- A new reporter can reach a monitored private security and conduct channel without already having a trusted personal relationship.
- The owner confirms maintainer responsibility, receipt expectations, escalation, and public-safe disclosure handling.
- The owner approves the public repository host and release target before publication.
- The owner explicitly approves the final 1.0.0 commit and annotated tag after reading the validation and review dispositions.

## Stop rule

Do not describe, commit, tag, or publish a tree as the final v1.0.0 release while any required gate is `PENDING`, `IN PROGRESS`, `DEFERRED`, `BLOCKED`, or `FAILED`. A release candidate may be committed for immutable review if it is labeled clearly and carries no v1.0.0 tag.
