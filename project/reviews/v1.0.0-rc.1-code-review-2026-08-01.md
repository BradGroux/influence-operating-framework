# v1.0.0-rc.1 code review

**Status:** PASS after fixes

## Method

Two independent read-only agents reviewed the full candidate diff on separate axes. The standards reviewer checked repository conventions, governance, schema rules, release criteria, and maintainability smells. The specification reviewer checked the accepted A/B review dispositions and v1.0.0 release requirements. Both ran or reproduced relevant checks against isolated temporary copies; neither edited the repository.

## Standards-axis findings and disposition

| Severity | Finding | Disposition |
| --- | --- | --- |
| High | Extension key prohibitions recognized `_` boundaries only and omitted bare key material. | Fixed. Schema and validator now recognize `.`, `-`, and `_` boundaries and reject key material; a shared negative vector exercises both gates. |
| High | A missing or empty `--baseline-root` passed as an empty comparison. | Fixed. The graph gate now fails unless the authoritative root contains JSON records. |
| Medium | Unknown contribution and commitment schedules did not require a reason. | Fixed. Both use the structured-unknown convention and have positive/negative tests. |
| Medium | The schema 1-to-2 migration omitted the required deprecation window. | Fixed. The guide now defines a 90-day transition boundary and states that the current validator is 2.0.0-only. |
| Low | The accepted v1 maturity gate lacked an ADR. | Fixed. ADR-001 records alternatives, decision, consequences, and amendment path. |
| Low | Extension policy was duplicated in schema and Python. | Mitigated. JSON Schema and runtime validation remain necessarily separate, while one test vector now exercises the same prohibited forms through both gates. |

## Specification-axis findings and disposition

| Severity | Finding | Disposition |
| --- | --- | --- |
| Blocker | Extension safety remained bypassable with punctuation-separated keys. | Fixed by the standards-axis extension changes. |
| Blocker | Do-not-contact precedence checked the recipient person but not linked relationship and opportunity decisions. | Fixed. An approved outreach is rejected when the linked person, relationship, or contribution-linked opportunity ends in `do_not_contact`. |
| Material | An `evidence_ids` value could resolve to a non-evidence record. | Fixed. Every evidence-reference field must resolve to a record whose type is `evidence`. |
| Material | Approval expiry was not checked against decision time, and decision chronology compared timestamp text. | Fixed. Both checks compare parsed instants; approval expiry must not precede either the approval decision or record update. |

## Conclusion

No Blocker or Material finding remains from this code-review pass. Full repository validation and the fresh two-agent review of one exact committed candidate are still required. This report does not satisfy the separate qualified-human or operational release gates.
